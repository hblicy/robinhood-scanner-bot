# Robinhood Chain 纯扫描机器人可靠性修复设计

## 背景与目标

当前版本已经移除 `paper`、`live`、钱包、签名和交易广播路径，只保留 `watch`、`scan`、`check` 三个只读命令。复审确认的剩余风险集中在错误被吞掉、游标过早推进、数据源耦合、配置加载过宽、网络请求无超时及本地状态并发覆盖。

本次目标是修复这些已确认缺陷，确保：核心分析不完整时不会把候选永久标记为已处理；一次性扫描能用退出码准确反映失败；关闭链上扫描后不访问 RPC；外部故障有界、可见、可重试；程序仍然只有扫描与推送功能。

## 范围

### 包含

- 核心分析数据的完整性判定及可重试失败。
- `watch` 和 `scan` 的数据源隔离、错误传播和退出语义。
- 链上事件解析失败、确认区块、RPC 重试和日志分块策略。
- GeckoTerminal 时间戳和分页失败处理。
- 扫描配置白名单加载及严格校验。
- Telegram 请求超时。
- `seen` 数据正确性、状态临时文件唯一性和 `watch` 单实例保护。
- 报告中显示辅助数据源失败。
- 对应回归测试、文档和只读冒烟验证。

### 不包含

- 不创建、签名、授权或广播交易。
- 不恢复模拟仓位、实盘交易、止盈止损或私钥使用。
- 不修改或删除用户现有 `.env`，即使其中保留旧交易字段。
- 不升级依赖，不重排目录，不清理无关历史文件。

## 数据完整性策略

采用用户确认的“核心数据失败重试、辅助数据降级”策略。

核心数据包括：token 合约字节码、ERC-20 基础元数据，以及候选对应的 DexScreener 市场绑定。核心 RPC 调用失败、市场请求失败，或新池尚未被 DexScreener 索引时，分析抛出带数据源上下文的可重试错误。调用方不得写 `seen`；链上候选所在区间不得推进游标。候选超过严格的 `MAX_AGE_MINUTES` 后记录为超龄跳过，使被延迟索引的永久空结果不会无限阻塞。

辅助数据包括 Blockscout holders、token、创建者和部署者历史，以及不影响 token/市场身份确认的风险补充数据。辅助调用失败时保留错误来源，相关事实标记为未知，继续评分和推送。告警正文及终端报告显示失败的数据源，避免把“未知”误读为“安全”。

## 扫描与游标流程

`watch` 将链上和 GeckoTerminal 作为两个独立任务执行。只有 `ONCHAIN_SCAN=true` 时才读取区块高度、计算初始边界或维护链上游标。链上任务失败只影响链上当轮；Gecko 仍按自己的周期执行。Gecko 失败也不会阻止链上任务。

链上只扫描达到确认深度的安全高度。新增 `CONFIRMATION_BLOCKS`，默认值为 2，允许显式设置为非负整数。已确认高度小于或等于游标时不发起日志查询。工厂地址和事件 topic 已精确匹配的日志若无法解析，视为区间不完整并阻止游标推进；不会静默丢弃。

RPC 区块读取、时间边界二分和日志查询使用有界重试与短指数退避。日志查询从较大的分块开始，节点拒绝时递归缩小，减少公共 RPC 上扫描约 30 分钟区间所需的请求数。超过重试次数后保留原错误上下文并交给调用方。

`scan` 同时尝试所有启用的数据源。一个来源失败时仍处理其他来源已取得的候选，最后汇总来源错误和候选错误并抛出 `AggregateError`，因此 CLI 以非零状态退出。候选处理同样先完成所有可处理项，再汇总失败，不再把部分成功伪装成整轮成功。

## 时间与 Gecko 数据

Gecko pool 的 `pool_created_at` 必须能解析为有限时间戳。缺失或无效时间戳不会替换成当前时间，也不会被当成新池。超出 `MAX_AGE_MINUTES` 的候选在进入分析前严格跳过。

Gecko 请求、JSON 解析或任一已请求分页失败时向调用方抛出错误，不返回看似完整的空数组或部分数组。响应中单条结构不合法的数据记录会带上下文报告为来源错误，避免整页静默降级。

## 配置安全

配置模块使用 `dotenv.parse` 读取项目 `.env` 到局部对象，不再调用 `dotenv.config()`，因此不会把文件中的 `PRIVATE_KEY`、`MODE` 或其他旧字段注入 `process.env`。配置访问器只读取代码明确列出的扫描字段，并保持 shell 环境变量优先于 `.env` 的既有覆盖语义。

布尔值只接受 `true/false`、`1/0`、`yes/no`、`on/off`，其他拼写启动失败。数值按用途校验：时间窗口为正数；计数为正整数；百分比为 0 到 100；税率为非负有限数；分数为 0 到 100；市值和流动性阈值为非负有限数。`QUOTE_TOKENS` 必须非空且只包含 `WETH`、`ETH`、`USDG`。`ONCHAIN_SCAN` 和 `GECKO_SCAN` 至少一个为 true。

## 通知与状态

Telegram 每次 HTTP 请求使用 `AbortController` 设置有界超时，并保留现有最多三次重试。超时或最终失败继续向上传播，错误信息经过 URL 和凭据脱敏；失败候选不写 `seen`。

`markSeen` 保存调用方传入的真实 token 地址，候选复合键只作为 map key，不再覆盖 payload 中的 `token` 字段。

状态原子写入使用包含进程 ID 和随机片段的唯一临时文件，避免固定 `state.json.tmp` 冲突。`watch` 启动时通过排他锁文件确保同一数据目录只有一个实例；锁中记录 PID，当前 PID 仍存在时拒绝启动，失效锁在验证后可回收。进程正常退出时释放锁；异常退出依靠下一实例的失效锁检查恢复。`scan` 和 `check` 不创建锁或状态目录。

## 错误可见性

所有预期的外部数据错误都带来源名称和候选 token；非预期异常不使用空 `catch` 吞掉。`formatAlert` 增加“数据异常”行，列出辅助来源失败。quiet skip 日志同样包含错误来源摘要。

日志不输出 Telegram token、私钥、完整带认证 URL 或 RPC 路径。现有 URL 脱敏规则继续适用。

## 测试与验收

所有生产改动遵循测试先行，每个缺陷先添加能在当前代码上失败的最小回归测试，再实现最小修复。

重点覆盖：

- 核心依赖失败或市场尚未绑定时不写 `seen`、不推进游标。
- 辅助依赖失败仍生成报告，并显示失败来源。
- `scan` 在部分成功后以非零状态汇总失败。
- `ONCHAIN_SCAN=false` 时不调用任何 RPC，RPC 失败不阻断 Gecko。
- 精确 topic 的畸形日志导致区间失败。
- Gecko 缺失、无效和超龄时间戳不会进入分析；分页失败不返回部分成功。
- 无效布尔值、阈值、报价币和全关闭来源在启动时失败。
- 导入配置不会把 `.env` 的非白名单字段写入 `process.env`。
- Telegram 永不返回时按超时终止并重试，最终错误向上传递。
- 多实例锁、唯一临时文件和真实 token payload。
- 确认区块不会被提前扫描，RPC 边界和日志查询能重试。

最终验收运行完整 `npm test`、`git diff --check`、交易能力静态扫描，以及主网只读 `scan` 冒烟。公共 RPC 若持续拒绝请求，应明确记录环境限制；测试不得把网络失败表述为功能成功。同步正式目录前再次比较隔离分支与目标文件，保留 `.env`、`data/` 和用户并行修改。
