# 纯扫描推送机器人设计

## 目标

将机器人收敛为只读分析与告警工具。运行时不得构造钱包、签名交易、授权代币、广播交易、维护模拟或实盘仓位，也不得因历史状态中的 pending 交易而产生链上写操作。

## 命令与外部行为

- `npm start` 与 `npm run watch`：持续监听链上和 GeckoTerminal 候选，分析、评分、输出终端报告；配置 Telegram 后发送告警；持久化 seen 与成功处理的链上区块游标。
- `npm run scan`：一次性扫描并输出终端报告，不写 `data/`，不发送 Telegram。
- `npm run check -- <token>`：分析指定代币并输出终端报告，不发送 Telegram、不写状态。
- `paper` 和 `live` 命令不再受支持；传入时立即以可识别错误退出，且在连接 RPC、读取状态或发送通知前完成拒绝。

## 代码收敛

- 删除 `src/trade.js` 及交易测试，移除所有调用点和交易相关 imports。
- 从 `package.json` 删除 `paper` 脚本。
- 从配置删除 `MODE`、`ENABLE_LIVE_TRADING`、`PRIVATE_KEY`、买入金额、gas、滑点、止盈止损和仓位轮询参数。
- 保留分析蜜罐所需的 V2 Router 地址和 ABI；这些只用于 `eth_call` 报价，不构造签名交易。
- `runtime.handleCandidate` 只负责分析、告警和 seen，不再接受或调用交易依赖。
- 通知文案固定说明“只扫描报警，不自动交易”，不再根据 live 门禁变化。

## 状态与兼容性

`state.json` 继续使用 schemaVersion 3。现有 `positions`、`trades` 字段作为历史只读数据保留，任何 seen 或游标更新都必须原样带回，禁止删除或改写用户历史交易记录。删除对外仓位/交易写 API，不再恢复或轮询历史仓位；首次导入旧文件时也只原样保留历史字段，不做交易状态转换。

新增 `cursors.onchain`，记录最后一个所有候选均成功处理的区块。旧状态缺少 `cursors` 时按空对象加载，不升级 schemaVersion，也不破坏旧文件导入。

## 扫描恢复与失败处理

首次启动或没有游标时，通过区块时间二分查找定位 `MAX_AGE_MINUTES` 对应的最早相关区块，不再使用固定 120 区块作为唯一补扫范围。已有游标时，从 `max(已保存游标, 年龄窗口起点前一块)` 继续，避免无意义处理已超过策略年龄的历史区块。

候选处理结果必须向调用方返回成功或失败。只要当前区间中任一候选分析或 Telegram 告警最终失败，就不提交该区间的游标；下一轮重新扫描相同范围。已成功候选由 seen 去重，失败候选因未写 seen 而重新处理。发现日志本身失败时沿用现有行为：不推进游标并在下一轮重试。

## 错误与秘密处理

错误消息中的任何 `http://` 或 `https://` 非空白片段整体替换为固定占位符，不尝试在任意文本中精确解析 URL 边。这样即使 URL 内含 `)`、IPv6、userinfo、path、query 或 fragment，也不会保留凭据后缀。banner 仍只显示协议和已脱敏主机占位。

## 测试与验收

- 回归测试证明 `paper`、`live` 在任何配置下都立即拒绝。
- 静态约束测试证明源码不再引用 `Wallet`、`signTransaction`、`broadcastTransaction`、swap/approve 等链上写入口，也不加载 `PRIVATE_KEY`。
- 测试失败候选会阻止游标提交，下一轮可重试；全部成功才提交游标。
- 测试旧 v3 状态在 seen/游标写入后仍完整保留历史 positions/trades。
- 测试首次启动按时间窗口定位区块。
- 测试包含右括号、IPv6、query 的错误 URL 被完整脱敏。
- 全归测试与全量源目录全量测试全部通过后，才同步到正式目录并再次运行全量测试。

## 非目标

- 不实现新的交易、回测、模拟仓位或收益统计。
- 不删除用户现有 `.env`、`data/` 或历史状态内容。
- 不改评分规则、第三方数据源或 Telegram 消息筛选策略。
